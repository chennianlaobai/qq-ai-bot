## 一、配置在哪 / 怎么生效

所有旋钮都收在两处，**散落在插件里的旧写法已经搬出来了**：

| 位置 | 放什么 | 改完要不要重启 |
|---|---|---|
| `.env`（照 `.env.example` 复制） | 凭据、模型、各种数值参数 | **必须重启后端** |
| 根目录数据文件 | `persona.md`（人设）、`persona_rules.json`（红线+密度规则）、`timetable.json`（课表） | **必须重启后端** |
| `表情包/<情绪>/` | 表情包图片 | 不用，实时读取 |

`.env` 里的值由 `config.py` 统一读取并校验：类型写错（比如 `HISTORY_MAX=abc`）、
范围写错（`HISTORY_USE` 大于 `HISTORY_MAX`、`MEM_ARCHIVE_MAX_CHARS` 大于上限）
会**在启动时直接报错**并告诉你去哪行改，不会带着错值默默跑。

### 必填

```
AI_API_KEY=ark-...                 # 当前：火山引擎 API Key
AI_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
AI_MODEL=deepseek-v4-flash-ga-260731
TARGET_GROUP=                      # 早安/晚安/上课提醒发到哪个群；留空=不发
```

### 全部可选参数（留着不用就取默认值）

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `AI_TEMPERATURE` | 0.95 | 越高越发散不套路，低了会一本正经（0~2） |
| `AI_TIMEOUT` | 90 | 单次请求超时（秒） |
| `AI_MAX_RETRIES` | 3 | 限流 / 5xx 自动重试次数 |
| `PRICE_IN` / `PRICE_OUT` / `PRICE_CACHE` | 3 / 9 / 0.1 | 元每百万 tokens，用于用量统计 |
| `HISTORY_MAX` | 20 | 每群内存里最多缓存多少条消息 |
| `HISTORY_USE` | 8 | 回复时带最近几条作上下文（≤ HISTORY_MAX） |
| `MAX_LEN_PER_MSG` | 120 | 单条消息截断字数，防爆 token |
| `AT_WINDOW` | 20 | 被 @ 后多少秒内补图也算发给它 |
| `MEM_CONSOLIDATE_EVERY` | 30 | 攒够多少条触发一次长期记忆合并 |
| `MEM_ARCHIVE_MAX_CHARS` | 800 | 档案字数上限（≤ MEM_MAX_USE_CHARS） |
| `MEM_MAX_USE_CHARS` | 1000 | 注入 prompt 的硬上限 |
| `MEM_PENDING_KEEP` | 200 | 待合并消息最多留多少条 |
| `BOT_NICKNAME` | 鲸鱼娘 | 昵称；`persona.md` 里必须出现同名，否则启动报错 |
| `ALLOW_GROUPS` | 空 | 群白名单，逗号分隔；留空=所有群都理 |
| `HOST` / `PORT` | 127.0.0.1 / 8080 | 监听地址，要和 NapCat 里填的反向 WS 对上 |
| `REPLY_LOG_MAX_BYTES` | 5,242,880（5 MB） | 回复日志滚动阈值（字节） |
| `REPLY_SPLIT_LINES` | true | 回复里有换行就**按行拆成多条消息发**（像真人打字分两条）；false=拼成一条 |
| `REPLY_LINE_GAP` | 0.6 | 拆开发时两条之间停几秒（0~10） |
| `REPLY_MENTION` | false | 回复要不要 **@ 对方**；默认 false（不加 @，更像群友自己搭话）。设 true 退回旧行为 |

**改完 `.env` 必须重启后端**才生效。

**可选模型（速度/效果为实测）：**

| 模型 | 速度 | 说明 |
|---|---|---|
| **`deepseek-v4-flash-ga-260731`** | ~2s | ⭐ 当前：火山方舟 DeepSeek-V4-Flash，演出最自然 |
| `glm-4.5-air` | ⚡ 0.6s | 智谱备选：最快，演出尚可 |
| `glm-4-flashx` | ⚡ 0.6s | 智谱最便宜（0.1 元/百万），灵动一般 |
| ~~`glm-4.7-flashx`~~ | 🐢 31.6s | 太慢，不建议 |

**换厂商只改 `.env` 三个值：**

| 厂商 | AI_BASE_URL | AI_MODEL |
|---|---|---|
| 火山引擎方舟 | `https://ark.cn-beijing.volces.com/api/v3` | `deepseek-v4-flash-ga-260731` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.5-air` |
| DeepSeek 官网 | `https://api.deepseek.com/v1` | `deepseek-chat` |

> ⚠️ 火山方舟的模型 ID 必须是**带 `-ga-` 的正式版**（`deepseek-v4-flash-ga-260731`），少一段会报 404。

## 二、改人设 / 性格

人设全部写在**根目录 `persona.md`** 里（原来塞在插件顶部的 `SYSTEM_PROMPT`，现在搬出来了，改文案不用碰代码）。启动时 `config.py` 会校验它非空、且包含 `BOT_NICKNAME` 指定的昵称。**当前人设 =「脑子好使、有点脾气」的群友**（"鲸鱼娘"是背景彩蛋，平时不刻意提）：

| 要素 | 当前设定 | 在 prompt 里找 |
|---|---|---|
| **核心定位** | 群里一个**脑子好使、有点脾气**的群友（不是 AI、不是宠物） | 开头 + 【怎么聊天】 |
| 回复长度 | 短：一句话为主，最多两句 | 第 1 条 |
| 智商 | 接得住话、听得懂梗、该犀利就犀利 | 第 2 条 |
| 脾气 | 不卑微、不讨好；谁说得不对就怼 | 第 3 条 |
| 损人互怼 | 嘴毒但损得聪明（禁真脏话/人身攻击） | 第 4 条 |
| 答疑态度 | 不用有问必答，可敷衍、可自顾自说 | 第 5 条 |
| 称呼 | 把群友当平级哥们/兄弟，不用"您" | 第 7 条 |
| 卖萌 / 颜文字 | **允许**：偶尔撒娇卖萌是调剂；点到为止，别句句都来 | 第 8 条 |
| **祝福语** | 被人求祝福时**第一句必须正经**（不玩梗不阴阳）；想皮就另起一行说第二句，两句不能揉一起 | 【祝福语】段 |
| **认人** | 上下文标了"谁说的"，别认错人 | 第 9 条 |
| **看图** | @你时带图 = 给你的，要像群友一样吐槽 | 【看图·像群友一样吐槽】 |
| 背景彩蛋 | 其实是鲸鱼娘，爱吃白饭、会甩尾巴 | 【背景彩蛋】 |
| 炸毛 | 被叫"大肥鱼 / 肥 / 胖"当场回怼 | 【背景彩蛋】段 |
| 表情包 | 结尾加 `[表情:情绪]` 触发发图；**能表达清楚时可只发图不写字** | 【表情包】 |
| 底线 | 可嘴贫但禁辱骂/歧视/涉黄、禁编造 | 【底线】 |

想调火候（更凶 / 更温柔 / 回复再短点 / 去掉炸毛），直接改对应那句即可。

**另外两个调情绪的旋钮**（都在 `ai_group.py`）：

| 参数 | 当前值 | 作用 |
|---|---|---|
| `AI_TEMPERATURE`（在 `.env` 里） | 0.95 | 越高越发散、越不套路；低了会一本正经 |
| `IMAGE_ANGLES`（在 `ai_group.py` 里） | 10 个角度 | 看图时随机抽一个注入，逼它每次换说法 |

### 「分成两句」是怎么落地的

人设里「祝福语先正经一句、想皮就再补一句」这类要求，靠**让模型用换行分段写**来表达。
`REPLY_SPLIT_LINES=true`（默认）时后端会**按行拆成多条消息发**，中间停
`REPLY_LINE_GAP` 秒（默认 0.6），看起来就是真人分两条打的：

```
祝你生日快乐，新的一岁顺顺利利
（停 0.6 秒）
可惜你又老了一岁，绷不住了 [表情包]
```

- **默认不带 @**（`REPLY_MENTION=false`）：被 @ 才会回，但回的时候不艾特对方——
  群里真人聊天很少句句 @，加了反而像客服播报。想退回「@某人 + 内容」就设
  `REPLY_MENTION=true`（此时首行是 `@某人 正文`，后面几行仍然不带 @）。
- 单行回复 → 就是一条消息，行为跟以前一样（区别只是不带 @）。
- 多行 → 拆成多条，`[表情:情绪]` 对应的图贴在**最后一条**上。
- 想回到「一条消息里塞两段」的旧行为：`.env` 里 `REPLY_SPLIT_LINES=false`。
- 定时推送（早安/晚安/上课提醒）走同一套规则。

> 触发和回复是两回事：**触发**仍然认 @（见第七节），去掉的只是**回复里的 @**。

## 四、长期记忆（跨重启记得住人）✅

**它怎么工作**：平时把群消息攒进缓冲，攒够 **30 条**（或每天凌晨 4:30 兜底）就交给模型**合并成一份「档案」**——只留值得长期记的（谁是谁、偏好、习惯、约定），日常寒暄和一次性话题不记。之后每次回复都会带上这份档案。

**关键：档案是"可修正"的，不是只追加。** 合并时模型会输出三种操作：

| 操作 | 何时用 |
|---|---|
| `add` | 出现全新的事实 |
| `update` | 和已有条目**矛盾** → 用新的覆盖（不会两条并存打架） |
| `delete` | 已失效/已过时 → 删掉 |

所以档案大小是**恒定的**（上限 800 字），不会越用越长、越用越贵。

**在哪调**（都在 `.env` 里，改完重启）：

```
MEM_CONSOLIDATE_EVERY = 30    # 攒够多少条消息合并一次
MEM_ARCHIVE_MAX_CHARS = 800   # 档案字数上限（控住 token）
MEM_PENDING_KEEP = 200        # 待合并消息最多留多少条
```

**档案文件**：`memory/长期记忆.json`（同时存档案和待合并消息，重启不丢）。

**实测开销（真实 API 量）**：

| | 输入 tokens | 单次花费 | 每月（按每天 100 次） |
|---|---|---|---|
| 无长期记忆 | 824 | 0.0027 元 | ~8.1 元 |
| **有长期记忆**（档案 216 字） | 983（**+159，+19%**） | 0.0031 元 | ~9.4 元（**+1.2 元**） |
| 档案打满 800 字（上限） | 1413（+589，+71%） | 0.0044 元 | ~13.3 元（+5.2 元） |

另外**合并本身**也要花钱：一次约 **0.002 元**（输入 ~440 / 输出 ~60 tokens）。按每 30 条合并一次算，几乎可忽略。

> 💡 想清空记忆：直接删掉 `memory/长期记忆.json`（或把里面某个群的数据删掉）再重启。
> 💡 想手动查看它记住了什么：直接打开 `memory/长期记忆.json`。
> ⚠️ 实测火山这个模型的 `cached_tokens` 恒为 0（**没有命中前缀缓存**），所以上面是**按 3 元/百万足额计**的真实数字，没有再打折。

## 五、看图（群友发图它能看懂）✅

当前模型（火山 DeepSeek-V4-Flash）**自身就支持看图**，无需额外配置。

**两种触发方式（都行）：**

1. **@机器人 + 同一条消息带图** → 直接看图回应
2. **先 @机器人 一句，再单独发图**（20 秒内）→ 也当成发给它的（QQ 表情包有时没法跟 @ 放同一条消息）

| 情况 | 反应 |
|---|---|
| @它 + 图（同条） | ✅ 看图吐槽 |
| @它 后 20 秒内补图 | ✅ 看图吐槽 |
| 只发图、不 @ 它 | ❌ 不理（群里图太多，不该乱插话） |

- **想调行为**：改 `SYSTEM_PROMPT` 里的【看图】
- **想调时间窗口**：改 `.env` 里的 `AT_WINDOW`（默认 20 秒）

> 原理：插件从消息里取出图片链接，以多模态 `image_url` 形式传给模型。一张图约 **+28 tokens**，很便宜。

## 六、加表情包（当前共 **34 张**）

1. 准备表情包图片（`.jpg / .png / .gif`，**动图也行**）
2. 按情绪丢进 `表情包/<情绪>/` 文件夹
3. 机器人会自己判断何时发、发哪种情绪

**当前库存**（卖萌 7 / 无语 6 / 得意 6 / 震惊 5 / 开心 4 / 委屈 3 / 生气 3）：

| 情绪 | 文件夹 | 张数 |
|---|---|---|
| 开心 | `表情包/开心/` | 4 |
| 无语 | `表情包/无语/` | 6 |
| 生气 | `表情包/生气/` | 3 |
| 卖萌 | `表情包/卖萌/` | 7 |
| 得意 | `表情包/得意/` | 6 |
| 委屈 | `表情包/委屈/` | 3 |
| 震惊 | `表情包/震惊/` | 5 |

> 某情绪文件夹空着 → 自动从「表情包」根目录随机选；全空 → 只发文字。
> 支持的文件夹名：开心、无语、生气、卖萌、得意、委屈、震惊。

> 💡 表情包是**实时读取**的，丢进去就生效，**不用重启后端**。

## 七、定时任务（早安 / 晚安 / 上课提醒）✅

**课表和推送时刻在根目录 `timetable.json` 里改**，群号和提前量在 `.env` 里改——都不用碰代码：

```
# .env
TARGET_GROUP=<你的群号>   # 发到哪个群；留空=不发
REMIND_BEFORE=20          # 课前提前多少分钟提醒
```

```jsonc
// timetable.json
{
  "remind_before": 20,
  "morning_hour": 6, "morning_minute": 0,     // 早安
  "night_hour": 23, "night_minute": 0,        // 晚安
  "period_start": { "1": "08:00", "2": "10:00", ... },   // 节次 → 上课时间
  "timetable": {
    "1": [ { "period": 1, "name": "计算机图形学", "location": "教学楼N303" } ]
  }
}
```

`timetable.json` 写错会**在启动时报错**（星期越界、节次没有对应时间、缺课程名都会拦下来）。

**三个推送任务 + 一个维护任务：**

| 时间 | 任务 | 在文件里找 |
|---|---|---|
| 每天 06:00 | 早安 | `morning()` |
| 每天 23:00 | 晚安 | `night()` |
| 课前 `REMIND_BEFORE` 分钟 | 上课提醒（带课名 + 地点） | `class_reminder()` |
| 每天 04:30 | 长期记忆合并（兜底） | `daily_memory()` |

> 文案**不是固定模板**——都由 AI 按人设实时生成，每次不重样；带 `[表情:情绪]` 标记时会自动配一张表情包。
> ⚠️ 定时任务要有网 + 机器人 QQ 在线才发得出去；后端窗口关了就不发（想省心 → 见维护日志里的「D1 开机自启」）。

## 十、体检：三件套（`tools/` 下 + `check.py`）

改完东西别急着等群里出问题，本地就能查：

| 命令 | 什么时候用 | 看什么 |
|---|---|---|
| `python check.py` | 改了 `.env` / 课表 / 人设之后 | 13 项自检：密钥、模型 ID、人设文件、表情包库存、课表、目录可写、端口、依赖。❌ 会拦住启动 |
| `python check.py --ping` | 换了 Key 或厂商 | 额外真连一次 `/models` 验证凭据 |
| `python tools/smoke_import.py` | 改了插件代码 | 不起服务，只验证插件能不能被 NoneBot 加载 |
| `python tools/secret_scan.py` | 提交代码前 | 全仓扫密钥 / token / 群号，命中一律打码显示 |
| `python tools/check_persona.py` | 想看它最近「像不像群友」 | 读最近回复打分，标出出戏的那几句 |
| `python tools/test_reply_chunks.py` | 改了「回复怎么发」（分段 / @ / 表情包位置） | 10 条用例单测：几行就拆几条、@ 有没有去掉、图贴哪一条 |

### 人格体检怎么用

```powershell
python tools/check_persona.py                       # 最近 50 条
python tools/check_persona.py --last 200 --group <群号>
python tools/check_persona.py --kind scheduled       # 只看早安/晚安/上课提醒
python tools/check_persona.py --text "您好，请问有什么可以帮您？"   # 单句速测
python tools/check_persona.py --text "祝生日快乐，绷不住了" --ask "祝我生日快乐"  # 带场景测
python tools/check_persona.py --strict               # WARN 也算失败（可以挂 CI）
```

输入是 `logs/replies.jsonl`——每轮回复（含定时推送）都会往里写一行 JSON，
超过 `REPLY_LOG_MAX_BYTES` 自动滚动成 `replies-<时间戳>.jsonl`。

判定规则在 **`persona_rules.json`**，不用改代码就能调尺度：

规则有三类，**别混淆**（改错地方会出现「放松了但还是被扣分」）：

| 区块 | 作用 | 典型用途 |
|---|---|---|
| `rules` | 逐句红线，命中一句就扣分 | AI 腔、自称 AI、用「您」、图片解说员 |
| `density_rules` | 允许出现，只管密度：太密才提醒 | 卖萌撒娇（见 D1） |
| `scene_rules` | 看「用户问了啥 + 它怎么答的」，只在这种场合生效 | 被求祝福时别把玩笑夹在第一句里（见 R15） |

| 字段 | 意思 |
|---|---|
| `limits` | 字数软/硬上限、最多几句、颜文字上限、复读相似度阈值 |
| `penalty` | 每条 error/warn 扣几分（起始 100） |
| `rules[].level` | `error` / `warn` / `off`（想放宽某条就改成 `off`） |
| `rules[].pattern` | 正则；写错了启动时会被自检拦下 |
| `density_rules[].window / min_hits / max_ratio` | 回溯窗口大小、窗口内至少命中几句、占比超过多少算超标 |
| `density_rules[].max_consecutive` | 连着几句之内算正常（当前 3），超出的从第 4 句起提醒 |
| `scene_rules[].trigger` | 什么话算触发了这个场景（如用户说「祝我生日快乐」） |
| `scene_rules[].bless / rough` | 祝福词表 / 插科打诨词表，两个词同时出现在**第一句**里就算夹带 |

当前逐句红线 9 条（另 1 条放宽成 `off`）：AI/客服腔、自称 AI 或助手、用「您」、列点、
客服式收尾、真脏话越界、`[表情:xxx]` 标记没消化、回复里带 `[AI 出错]`、像图片解说员
（"这是一张…"）。

**卖萌撒娇不是红线**（`R6-fawn` 已置 `off`）：偶尔来一下是要的，属于人味儿；只在
`D1-fawn-density` 觉得太密时才提醒——默认「连着超过 3 句」或「最近 10 句里超过一半」才触发，
所以单句卖萌 `--text` 速测是满分。想彻底不检查就把 `D1` 的 `level` 改成 `off`；
想罚得更狠就把 `max_consecutive` 调小。

**祝福语是「场景规则」`R15-blessing-mixed`**：用户求祝福时，**开头第一句必须干净**——
同一句里不能既有祝福词又有「哈哈/草/xswl/就这」这类皮话，正经和不正经要分成两句。
`祝生日快乐，可惜你又老了一岁绷不住了` ✗ ／
`祝你生日快乐，新的一岁顺顺利利` + 换行 + `可惜你又老了一岁，绷不住了` ✓。
第二句往后随便皮，不查。

> 单句调试最快：`--text "你想试的那句话"`；要连场景一起测就再加 `--ask "用户说了什么"`。
